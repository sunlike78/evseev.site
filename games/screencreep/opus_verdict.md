# ScreenCreep — экспертный разбор

Оцениваю по описанной архитектуре и дизайн-спеке; где нужны цифры — даю конкретные, где вижу риск — называю его прямо, без смягчения.

## 1. ТЕХНИЧЕСКАЯ НАДЁЖНОСТЬ И АРХИТЕКТУРА

### 1.1. Master Ticker в PixiJS v8 — где вы уже правы и где вас укусит

**Ловушка №1 (v8-специфичная).** В v8 сигнатура коллбэка сменилась: `ticker.add((ticker) => ...)` отдаёт **инстанс Ticker**, а не число. Половина миграционных багов «всё летает в 60 раз быстрее» — отсюда. Если у вас где-то остался `(delta) => x += speed * delta` — это тихая бомба.

**Ловушка №2.** Pixi уже клампит время сам: `Ticker.minFPS = 10` по умолчанию → `_maxElapsedMS = 100ms`. Это значит, что **ваш аккумулятор никогда не получит правдивый deltaMS после возврата из фона** — Pixi отдаст 100 мс, а не 47 000 мс. Это хорошо (нет спирали), но фатально, если вы наивно копите оффлайн-прогресс через симуляцию. Вывод: **Ticker — это не источник истины о времени. Источник истины — `performance.now()` + отдельный `WallClock`, сверяемый с `Date.now()` на предмет подкрутки системных часов.**

**Правильная топология тикера — три слоя, а не один:**

```
UPDATE_PRIORITY.HIGH      → TimeAuthority  (замер, кламп, аккумулятор, детект стал)
UPDATE_PRIORITY.NORMAL    → SimulationStep (N × fixed 16.667ms, детерминированный)
UPDATE_PRIORITY.LOW       → Interpolator   (alpha-lerp состояний sim[n-1]→sim[n])
UPDATE_PRIORITY.UTILITY   → GPU-only эффекты (шейдерное время, дрожь, шум)
```

Критично: **интерполяция обязана быть отдельным слоем**. Без неё фиксированный шаг на 144-Гц мониторе даёт заметный микро-джиттер именно на медленных, «желейных» движениях — а это ровно то, на чём держится ваш ASMR. Хранить `prev`/`curr` трансформы и лерпить по `alpha = accumulator / FIXED_DT` в Low-приоритете.

### 1.2. Спираль смерти: три независимых предохранителя

Один кламп — это не защита, это надежда. Нужны три:

```js
const FIXED_DT   = 1000 / 60;
const MAX_STEPS  = 5;              // 83 мс симуляции за кадр — потолок
const PANIC_MS   = 250;            // выше — считаем кадр «потерянным»

let acc = 0, last = performance.now();

function timeAuthority() {
  const now = performance.now();
  let raw = now - last;
  last = now;

  if (raw > PANIC_MS) {            // предохранитель 1: паник-дроп
    raw = FIXED_DT;                // не копим, а «телепортируем» время
    onTimeDiscontinuity(raw);      // помечаем разрыв для оффлайн-модуля
  }
  acc += raw;

  let steps = 0;
  while (acc >= FIXED_DT && steps < MAX_STEPS) {   // предохранитель 2
    sim.step(FIXED_DT);
    acc -= FIXED_DT;
    steps++;
  }
  if (steps === MAX_STEPS) acc = 0;                // предохранитель 3: сброс долга
}
```

**Отдельно — Page Visibility.** Не полагайтесь на то, что rAF просто «встанет». Chrome душит фоновые вкладки до 1 Гц, iOS Safari может убить контекст, а `visibilitychange` на мобильных иногда не приходит при свайпе вверх. Схема:

- `visibilitychange → hidden`: `ticker.stop()`, **фиксируем `hiddenAt = Date.now()` в память И в `localStorage`** (второе — на случай, если вкладку выгрузят из памяти без `pagehide`).
- `visible`: `elapsed = Date.now() - hiddenAt`, прогоняем через **аналитическую (closed-form) модель оффлайн-прогресса**, не через симуляцию. Затем `last = performance.now()` и только потом `ticker.start()`.
- Дополнительно слушать `pagehide` и `freeze`/`resume` (Page Lifecycle API) — на мобилках это единственные надёжные точки.

**Оффлайн-прогресс закрытой формулой — не опция, а требование.** Для экспоненциального роста `P(t) = P0 · e^{rt}`, для сатурирующего — логистика. Если у вас нелинейные взаимодействия (creep ест DOM → меняет скорость роста), делайте **кусочно-аналитический интегратор**: разбиваете оффлайн на 20–50 сегментов, внутри каждого коэффициенты считаются константами. 50 шагов вместо 43 200 — и модель остаётся честной.

### 1.3. GPU-матрицы vs тесселяция — здесь у вас главный архитектурный выбор

Вы формулируете это как дихотомию, но реально вариантов **четыре**, и они дают разный game feel:

| Подход | Стоимость | Что даёт | Когда |
|---|---|---|---|
| **2×2 деформация** (non-uniform scale + skew по вектору скорости) | ~0, часть трансформа | Классический squash&stretch. Дёшево, читаемо | Прыжки, удары, отскоки |
| **MeshPlane 8×8** (81 верт) | CPU-запись буфера каждый кадр | Локальные волны, «желе» | 1–20 существ максимум |
| **Кастомный вертексный шейдер** на квадe | GPU, ~0 CPU | Синусоидальные волны, дыхание, wobble по uniform | Сотни существ |
| **SDF-метаболы во фрагментнике** (smooth-min union) | Fillrate | **Слияние/деление капель, настоящая «слизь»** | Ядро визуала |

**Моя рекомендация: SDF-метаболы как основа + 2×2 матрица как «нервная система».**

Причина не техническая, а дизайнерская: `smin()` даёт вам **бесплатную эмерджентную механику** — капли, подползая друг к другу, физически сливаются в одну, а при разрыве тянут перемычку. Это ровно тот визуал, ради которого люди пересматривают ролики со слаймом. Тесселяция такого не даст никогда, а стоит дороже.

Как удержать fillrate: рендерить метаболы в `RenderTexture` половинного разрешения (0.5×), потом апскейл с трешхолдом в фильтре. Мягкость краёв прячет апскейл полностью. Экономия 4× по пикселям. Уникальные капли ограничьте 32–48 в uniform-массиве, остальное — в пространственный хэш и не передавайте в шейдер то, что за экраном.

**И обязательно: `renderGroup` из v8.** Всё статичное поддерево (фон, HUD, «пожёванные» DOM-двойники) — `new Container({ isRenderGroup: true })`. Это переносит перемножение матриц на GPU и убирает обход дерева на CPU. На сцене с 500+ объектами это разница между 6 мс и 1.5 мс на кадр.

Ещё: `GraphicsContext` в v8 переиспользуется между инстансами — тесселяция считается **один раз на контекст**. Если вы создаёте `new Graphics()` на каждую каплю с одинаковой формой — вы тесселируете N раз вместо одного. `new Graphics(sharedContext)`.

### 1.4. Утечки — реальный чеклист, а не «не забудьте destroy»

Топ-6 источников утечек именно в вашем типе игры:

1. **Замыкания в тикере.** Каждая капля добавляет `ticker.add(this.update, this)` — и не снимает. `ticker.remove(fn, context)` **обязателен в `destroy()`**, иначе у вас растёт связанный список коллбэков, и после часа игры кадр стоит 40 мс на мёртвых объектах. Лучше вообще: **никаких индивидуальных тикеров**. Одна система обходит SoA-массив.

2. **`Text` в v8.** Каждый инстанс `Text` — это отдельная текстура + канвас-раскладка. Ваши «редкие фразы», всплывающие цифры комбо, счётчики — если это `Text`, обновляемый каждый кадр, вы порождаете текстурный мусор с бешеной скоростью. **Всё, что меняется чаще раза в секунду → `BitmapText`.** Фразы-награды — можно `Text`, но с пулом на 8 инстансов и переиспользованием.

3. **`destroy()` с неправильными опциями.** `destroy({ children: true })` — но `texture: false`, если текстура из `Assets` и шарится. И наоборот: динамические `RenderTexture` (ваши метабол-таргеты, снапшоты для виральных артефактов) **не собираются автоматически**, только явный `renderTexture.destroy(true)`.

4. **Фильтры.** `Filter` держит GPU-ресурсы и uniform-группы. Присвоение `container.filters = [new GlowFilter()]` в горячем коде = гарантированная утечка. Фильтры — синглтоны, создаются на старте, параметры меняются через uniforms.

5. **DOM-слой Breach Mode.** Здесь самое опасное: вы вешаете листенеры на реальные элементы страницы, `MutationObserver`, `ResizeObserver`, `IntersectionObserver`. **Каждый Observer должен иметь владельца и `disconnect()` в едином `BreachSession.teardown()`.** Плюс `WeakRef`/`FinalizationRegistry` для отслеживания «съеденных» узлов, чтобы не держать сильные ссылки на удалённые DOM-элементы.

6. **Потеря WebGL-контекста.** На iOS при переключении вкладок контекст умирает регулярно. Pixi v8 частично это переживает, но ваши кастомные шейдеры и RenderTexture — нет. Обработчик `webglcontextlost` → `preventDefault()` → `webglcontextrestored` → **пересоздание рендера из состояния симуляции**. Это возможно бесплатно, если выполнить рекомендацию №1 из третьего раздела.

**Инструментальное требование:** DevTools → Memory → три heap snapshot'а с интервалом 5 минут при 10-кратном ускорении симуляции. Кривая `Detached HTMLElement` и количество `Texture` должны быть плоскими. Если растут — это не «немного мусора», это краш через 40 минут сессии. А ваша игра — про длинные сессии.

**Оценка раздела: 7.5/10 при описанном подходе.** Фундамент верный, но три вещи (интерполяционный слой, closed-form оффлайн, дисциплина тикера) отделяют «работает у меня» от «работает у 50 000 человек в разных браузерах».

## 2. GAME FEEL, МЕТА-ХОРРОР И ПСИХОЛОГИЯ УДЕРЖАНИЯ

### 2.1. ASMR-сквиши: аудио важнее визуала, и вы это, скорее всего, недооцениваете

Слайм-ASMR работает на **транзиенте**, а не на теле звука. Формула одного сквиша — три слоя:

- **Attack (0–15 мс):** резкий влажный клик. Именно он даёт мурашки.
- **Body (15–120 мс):** резонирующее «чмок», питч зависит от размера капли.
- **Tail (120–400 мс):** воздушный шёпот, микро-разрывы.

Критические требования, без которых всё разваливается:

1. **Round-robin пул 6–10 сэмплов** на каждый тип. Три — мало, ухо ловит повтор за 20 секунд и звук становится раздражающим.
2. **Микро-детюн ±35 центов случайно** + рандомный старт-офсет 0–8 мс. Это то, что превращает «звук из игры» в «органический звук».
3. **Питч обратно пропорционален размеру:** `playbackRate = clamp(1.4 - 0.5 * log2(size), 0.6, 1.8)`. Большие капли — низкие, сочные. Это даёт бесплатную читаемость масштаба на слух.
4. **Web Audio API, не HTMLAudioElement.** И `AudioContext.resume()` на первом жесте, иначе на Safari вы просто немые.
5. **Динамическая компрессия на мастере** + **ducking** при комбо, иначе на 40 сквишах в секунду вы получите клиппинг и физическую боль в наушниках.

**Правило, которое чаще всего нарушают:** сквиш должен звучать **до пика анимации, а не в момент касания**. Задержка звука на 0 мс, а анимация деформации стартует за 30–40 мс до этого (anticipation) — тогда мозг читает удар как «весомый». Аудио-первый тайминг — это половина game feel.

### 2.2. Комбо-стрики: питч-лестница и её потолок

Стандартная реализация — полутон за комбо — ломается на 20-м: звук уходит в писк и становится наказанием.

**Правильно:** мажорная пентатоника по кругу (0, 2, 4, 7, 9 полутонов), поднимая октаву каждые 5 шагов, **с потолком на +2 октавы**. Дальше не питч, а **плотность**: добавляется второй слой, третий, шиммер. Игрок слышит «больше», а не «выше». Плюс лоу-пасс, который открывается с комбо — ощущение «нарастающей ясности».

**И обязательно — асимметрия потери.** Обрыв комбо должен звучать не как «неудача», а как **резкий вдох и тишина на 400 мс**. Пустота после насыщенного слоя болезненнее, чем любой звук провала. Это же — идеальная точка для «дыхания» перед следующей фразой-наградой.

### 2.3. Breach Mode и поедание DOM — честная оценка риска

Это ваш главный козырь и **ваша главная точка отказа**.

**Почему это работает:** нарушение контракта «игра живёт в прямоугольнике» — это единственный трюк, который нельзя воспроизвести в трейлере, но можно воспроизвести в **записи чужого экрана**. Отсюда виральность Pony Island и Doki Doki: люди делятся не игрой, а *реакцией на нарушение*.

**Почему это ломается:** трюк одноразовый. Первый выход за рамку — 10/10. Второй — 6/10. Третий — игрок понимает грамматику и начинает *ожидать*. Ожидаемое нарушение — это уже не нарушение, это механика. Игры, которые здесь проваливаются (а их большинство), делают одно и то же нарушение с нарастающей интенсивностью. Работает только **смена категории нарушения**.

**Лестница эскалации (5 ступеней, каждая — новая категория):**

1. **Canvas** — существо трогает края, отскакивает от них.
2. **Chrome страницы** — вылезает поверх UI игры, ест кнопки, скроллбар, курсор (`cursor: url(...)` с искажённой стрелкой).
3. **Документ** — жуёт реальные DOM-узлы страницы, `document.title` начинает дёргаться, favicon мутирует.
4. **Браузер** — вкладка «дышит» (анимированный title), Notification API шепчет, `navigator.vibrate` на мобильном.
5. **Игрок** — игра называет то, что знает: время суток, разрешение экрана, язык, сколько минут назад он вернулся из другой вкладки, был ли он тут вчера. **Это самая дешёвая и самая разрушительная ступень.**

Пятая ступень требует хирургической точности: одна фраза, один раз, в паузе тишины. `«03:47. Ты снова не спишь.»` — это работает. Три таких подряд — это уже алгоритм, и магия умирает.

**Правовые/этические ограничители, которые нельзя игнорировать:** не имитируйте системные диалоги ОС, не имитируйте потерю данных, не блокируйте закрытие вкладки через `beforeunload`-спам. Люди пишут негативные отзывы и жалобы в сторы именно за это, а не за страх. Граница: **«игра нарушает границы своего окна» — да; «игра создаёт впечатление, что ломает компьютер» — нет.**

**Обязательно:** уважение `prefers-reduced-motion`, предупреждение о вспышках, и **диегетическая настройка интенсивности** — существо само спрашивает, насколько глубоко ему можно. Это не портит хоррор, а усиливает его: акт согласия делает игрока соучастником.

### 2.4. Почему фразы-награды должны быть редкими — механика, а не вкусовщина

Три причины, все считаемые:

**Плотность семантики.** Текст, появляющийся чаще 1 раза в 90 секунд, мозг переклассифицирует из «сообщение» в «декор» и **перестаёт читать**. Это порог, а не градиент. Переход происходит примерно на 8–10-м повторении формата.

**Вариативное подкрепление.** Фиксированный интервал даёт привыкание, случайный — устойчивое к угасанию поведение (классика Скиннера, и это то, на чём стоят все успешные инкременталки). Но: **вариативность должна иметь пол**. Чистый random даёт «сухие» сессии в 15 минут без единой фразы — игрок уходит. Решение — **pity-таймер**: базовый шанс 0.4%, растущий на 0.05% за каждое событие без выпадения, сброс после выпадения. Средний интервал ~2.5 минуты, гарантированный потолок ~6 минут.

**Артефактность.** Редкое → достойно скриншота. Частое → не достойно. Это прямой контроль над виральностью через одну константу.

**Дополнительно:** фразы должны иметь **тиры редкости с разной интонацией**. 85% — наблюдения (нейтральные, атмосферные). 12% — обращения (переход на «ты»). 3% — знание (пятая ступень эскалации, персональные данные). Игрок быстро учится различать тиры и начинает **охотиться на третий**. Вот это и есть удержание.

### 2.5. Виральный артефакт — конкретная спецификация

Скриншот игры не виралится: он не читается за 1.5 секунды в ленте и не содержит крючка. Нужны три вещи одновременно:

1. **Автоклип, а не скриншот.** Кольцевой буфер `MediaRecorder` поверх `canvas.captureStream(30)`, постоянно пишущий последние 8 секунд. При событии Breach — дамп в WebM/MP4. Кнопка называется не «Поделиться», а **«Сохранить запись инцидента»**. 6–8 секунд — точная длина лупа для TikTok/X.

2. **Именованный артефакт с сид-кодом.** Каждый creep детерминированно генерируется из сида. Итоговая картинка — «карточка образца»: силуэт, имя (процедурное, произносимое), стадия, сколько DOM-узлов съел, и **короткий share-код**. Другой игрок вводит код — получает **тот же самый организм**. Это превращает шеринг из хвастовства в обмен объектами, а объекты копятся и коллекционируются.

3. **Крючок для зрителя, а не для игрока.** Артефакт должен содержать фразу, адресованную **тому, кто смотрит**, а не тому, кто играл: `«Этот образец теперь знает и о твоём экране тоже.»` Зритель — следующий заражённый. Это единственная механически честная реализация «вирусности» в мета-хорроре, и она стоит вам одной строки текста.

**Оценка раздела: 8.5/10 по концепции, 5/10 по риску исполнения.** Идеи первоклассные, но 80% таких проектов гибнут на п. 2.3 — эскалация выдыхается на 15-й минуте.

## 3. ТОП-3 РЕКОМЕНДАЦИИ

### №1 (архитектура). Разделить на детерминированное симуляционное ядро и презентационную оболочку — **прямо сейчас, до наращивания контента**

Headless-модуль без единого импорта из `pixi.js`: seeded PRNG (xorshift128+, не `Math.random`), фиксированный шаг, состояние в типизированных массивах, интерфейс `step(dt) → State`. Pixi, DOM-слой Breach, аудио — три независимых **подписчика** на состояние.

Что это разблокирует одним движением:
- **Оффлайн-прогресс** становится вызовом того же ядра с ускорением — никаких двух расходящихся реализаций экономики.
- **Восстановление после потери WebGL-контекста** — бесплатно: рендер пересоздаётся, состояние живо.
- **Виральный share-код** — это просто сид. Детерминизм даёт вам механику воспроизводимых организмов даром.
- **Реплей** — лог входных событий вместо видео, весит килобайты, воспроизводится точно. Это и дебаг, и артефакт.
- **Античит и целостность сейва** — хеш состояния каждые N шагов.
- **Breach Mode как «второй рендерер»**, а не как хак поверх игры. Сейчас, судя по описанию, DOM-слой рискует стать спагетти с прямыми ссылками на спрайты. Это худший класс технического долга в вашем проекте.

Стоимость сейчас — 3–5 дней рефакторинга. Стоимость через два месяца контента — три недели и потеря половины фич.

### №2 (геймдизайн). Сделать поедание UI **системным**, а не декоративным: «Экономика Аппетита»

Сейчас поедание DOM — это спецэффект. Это трата вашего лучшего актива на визуал.

Урок Universal Paperclips: **интерфейс — это и есть игра**. Кнопка = глагол. Значит, съеденная кнопка = **потерянный глагол**, и это должно быть решением игрока.

Механика: creep периодически голоден и **указывает на элемент интерфейса**. Игрок выбирает:
- **Скормить** — элемент исчезает **навсегда в этом прогоне**, вы теряете действие, но creep эволюционирует, открывая новую способность/множитель.
- **Отказать** — creep слабеет, замедляется, но интерфейс цел.

Это даёт вам сразу:
- **Реальные ставки в мета-механике.** Страх становится функциональным, а не косметическим.
- **Ветвление билдов.** Разные жертвы = разные прогоны. Реиграбельность без нового контента.
- **Естественная кривая эскалации.** К концу прогона интерфейс — руины, и игрок сам это построил. Это гораздо сильнее любого скриптованного хоррора: **игрок не жертва, а соучастник.**
- **Финал сам себя пишет.** Последний оставшийся элемент интерфейса и есть последнее решение прогона.

Правило пейсинга поверх этого: **бюджет тишины**. После каждого крупного нарушения — 60–90 секунд абсолютно обычной, спокойной игры. Хоррор существует только в контрасте. Непрерывная жуть — это не жуть, это фон.

### №3 (дизайн + техника). Построить «Архив Шёпота» — превратить редкие фразы из событий в коллекционируемую систему

Одна фраза, показанная и исчезнувшая, — это 4 секунды дофамина. Та же фраза, попавшая в персональный архив с меткой времени, номером и статусом «редкое» — это долгосрочный крючок.

Конкретно:
- Постоянный, переживающий рестарты **журнал**: 120–150 записей, разбитых по тирам, с прочерками на неоткрытых.
- **Полоса заполнения**. Незакрытый список — сильнейший из известных ретеншн-механизмов, и он не стоит ничего.
- Каждая запись **экспортируется** как готовая карточка (тёмная, вертикальная, с сид-кодом) — генерируется в `OffscreenCanvas` в воркере, чтобы не ронять кадр.
- **Мета-твист поверх архива:** записи со временем начинают **меняться**. Игрок открывает то, что видел вчера, и текст другой. Это отдельная ступень эскалации, не требующая ни единого нового спрайта, — и она бьёт сильнее любого выхода за рамку, потому что атакует не экран, а **память игрока**.

## Итоговый вердикт

**ScreenCreep — это проект с редким сочетанием: тактильная петля, которая держит сама по себе (ASMR-сквиши), и концептуальный крючок, который продаётся сам (breach).** Такие сочетания встречаются раз в несколько лет. Но:

- **Технически** вы в одном рефакторинге от устойчивой платформы и в трёх утечках от массовых крашей на длинных сессиях. Симуляционное ядро — не «хорошо бы», а условие выживания фичи Breach.
- **Дизайнерски** ваш главный риск — не сложность, а **истощение новизны на 15-й минуте**. Мета-трюк без системной поддержки выгорает. Рекомендация №2 — единственный известный способ это починить.
- **Виральность** у вас достижима, но она требует явной инженерии (автоклип + сид + фраза для зрителя), а не «люди сами заскриншотят». Не заскриншотят.

Сделайте эти три вещи — и это не «ещё один кликер с приколом», а игра, о которой пишут разборы. Не сделайте — получите блестящую техно-демку с потолком в 20 минут внимания.
